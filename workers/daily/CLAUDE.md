# workers/daily/ — fixed training window

- The sliding-window size is `training_window_days` in `shared/shared/config.py` (default 21, override with the `TRAINING_WINDOW_DAYS` environment variable) and is stored in `models.params["window_days"]`.
- The daily and weekly trainers use every stored `BTCUSDT` daily row and fail with the required and available row counts when there are fewer than `(window + 1) * 5` (plus `horizon - 1` for the weekly model): `required_training_days()` in `workers/daily/trainer.py`.
- The trainers (daily, weekly, `train_all_models`) and the predictors (daily, weekly) call `require_fresh_series(series.dates, today)` (`shared/shared/features.py`) before building features. It needs the last bar dated `today - 1` (UTC) and consecutive days, otherwise it raises `ValueError` naming the missing dates: the job exits 1, saves no prediction row and creates no model row (#174). `workers.daily.__main__` stops at the first failing stage, so the exit code reaches Railway. The workers never fetch prices themselves: `fetch-price` backfills missed days on its next run. The backtest (`scripts/backtest_engine.py`) has its own loader and does not call this check.
